## 2. 商业版目标承载（v1.0）

### 2.1 单实例承载（推荐配置）

**硬件基线**：4 vCPU / 16 GB RAM / 200 GB SSD

| 承载维度 | 推荐上限 | 极限上限 | 备注 |
|---|---|---|---|
| **租户数量** | 100 | 500 | 每个租户独立数据空间 |
| **员工总数** | 50,000 | 200,000 | 跨所有租户合计 |
| **单租户员工** | 1,000 | 5,000 | 单家公司规模 |
| **日活用户 (DAU)** | 10,000 | 30,000 | 实际登录使用 |
| **并发请求 (QPS)** | 500 | 2,000 | 含读写混合 |
| **峰值打卡 QPS** | 1,000 | 3,000 | 早 9 点 / 晚 6 点峰值 |
| **API 响应时间 P50** | < 100 ms | < 300 ms | 中位数 |
| **API 响应时间 P95** | < 300 ms | < 800 ms | 95 分位 |
| **API 响应时间 P99** | < 800 ms | < 2 s | 99 分位 |
| **数据库连接池** | 50 | 200 | 连接数 |
| **文件存储** | 100 GB | 1 TB | 头像/票据/合同 |
| **每秒新增记录** | 100 | 500 | 含考勤/请假/报销 |
| **月数据增长** | 10 GB | 100 GB | 含审计日志 |

### 2.2 业务场景承载示例

#### 场景 A：100 人创业公司
- 1 个租户 / 100 员工
- 日打卡 2 次 = 200 请求/天
- 峰值 9:00–9:05 → 200 请求 / 5 分钟 = ~0.7 QPS
- 月薪资发放 1 次 = 100 计算
- 月度数据量：< 50 MB
- **结论**：v1.0 单实例可支撑 100+ 这种规模的客户

#### 场景 B：1000 人中型企业
- 1 个租户 / 1000 员工
- 日打卡 2000 次，峰值 6.7 QPS
- 月薪资 1000 计算 → 5-10 秒完成
- 月度数据量：~500 MB
- **结论**：v1.0 单实例可支撑 10 家该规模客户

#### 场景 C：5000 人大型企业
- 1 个租户 / 5000 员工
- 日打卡 10,000 次，峰值 33 QPS
- 月薪资 5000 计算 → 30-60 秒完成
- 月度数据量：~2 GB
- **结论**：建议独立部署 1 个实例（专属租户）

### 2.3 极限压测预期（基于 FastAPI + PostgreSQL）

```
单 API 端点：    8,000-15,000 RPS（无 DB 查询）
读操作：          2,000-4,000 RPS（DB 缓存命中）
写操作：          500-1,500 RPS（DB 写入）
薪资计算：        100-200 员工/秒
打卡操作：        2,000-3,000 次/秒
```

## 6. 横向扩展策略

### 6.1 应用层扩展（无状态）

- **触发条件**：CPU > 70% 持续 5 分钟，或 P95 响应时间 > 500ms
- **扩展方式**：Kubernetes HPA（自动横向扩缩容）
- **上限**：单服务最多 50 pods

### 6.2 数据库扩展

#### 6.2.1 读扩展
- 主从复制：1 主 + 3-5 只读副本
- 读请求自动路由到从库
- 报表查询专用从库

#### 6.2.2 写扩展
- **分库**（按租户 hash）：
  - DB-per-tenant（高价值客户）
  - Schema-per-tenant（中型客户）
  - Shared schema + tenant_id（小型客户）
- **分表**（按时间）：
  - 考勤表按月分表（`attendance_2026_05`）
  - 审计日志按周分表

#### 6.2.3 缓存层
- Redis 集群（6 节点起步，3 主 3 从）
- 热数据 TTL：
  - 员工档案：30 分钟
  - 部门列表：1 小时
  - 权限缓存：15 分钟
  - 仪表盘 KPI：5 分钟

### 6.3 文件存储扩展

- 对象存储天然分布式（S3 / OSS）
- CDN 加速大文件下载（工资条 PDF）
- 文件压缩：图片 WebP / PDF 压缩
- 冷数据归档（1 年以上）：S3 IA / Glacier

## 7. 安全与灾备

### 7.1 多层防护

```
┌─────────────────────────────────────────┐
│ L7：WAF (Web 应用防火墙)                  │
│     ・SQL 注入 / XSS / CSRF              │
│     ・OWASP Top 10 规则                  │
├─────────────────────────────────────────┤
│ L6：DDoS 防护                            │
│     ・CloudFlare / 阿里云 DDoS 高防       │
├─────────────────────────────────────────┤
│ L5：API 网关                              │
│     ・速率限制 (per user / per IP)       │
│     ・IP 白名单 (企业版)                  │
│     ・JWT 验证                            │
├─────────────────────────────────────────┤
│ L4：传输加密                              │
│     ・TLS 1.3                            │
│     ・证书自动续期 (Let's Encrypt)        │
├─────────────────────────────────────────┤
│ L3：数据加密                              │
│     ・静态 AES-256                       │
│     ・字段级（薪资/身份证）              │
│     ・KMS 密钥轮换                       │
├─────────────────────────────────────────┤
│ L2：访问控制                              │
│     ・RBAC + ABAC                        │
│     ・MFA / SSO                          │
│     ・会话管理                            │
├─────────────────────────────────────────┤
│ L1：审计与监控                            │
│     ・所有操作审计日志                    │
│     ・异常告警 (PagerDuty)                │
│     ・安全事件 SIEM                       │
└─────────────────────────────────────────┘
```

### 7.2 灾备方案

#### 7.2.1 同城双活
- 主备机房距离 > 30km
- 数据库实时主主同步
- 流量自动切换（< 30 秒）

#### 7.2.2 异地灾备
- 北京 → 上海 / 深圳（中国）
- 新加坡 → 香港 / 东京（亚太）
- RPO < 5 分钟 / RTO < 1 小时

#### 7.2.3 备份策略
- 每日全量备份 + 每小时增量
- 备份保留：30 天热备 + 1 年冷备
- 季度灾难演练

## 8. 部署模式

### 8.1 公有云 SaaS（主推）

- 客户直接订阅，无需自建
- 共享租户（默认）/ 专属租户（企业版）
- 数据驻留：客户可选 SG / CN / MY / HK

### 8.2 私有云部署

- 客户自有 IaaS（阿里云/腾讯云/AWS/Azure）
- 一键 Docker Compose / Helm Chart 部署
- 适合：金融、政府、医疗、央国企

### 8.3 本地化部署 (On-Premise)

- 客户机房物理服务器
- 包年许可证 + 定制开发
- 适合：超大型企业 / 涉密单位

### 8.4 部署模式承载对比

| 模式 | 推荐规模 | 部署周期 | 维护责任 |
|---|---|---|---|
| 公有云 SaaS（共享） | 10-500 人 | 即开即用 | 厂商 |
| 公有云 SaaS（专属） | 500-5000 人 | 1-3 天 | 厂商 |
| 私有云 | 1000-10000 人 | 1-2 周 | 客户+厂商 |
| 本地化 | 5000-100000 人 | 1-3 月 | 客户为主 |
